# 景区资料语义

来源可以是主管部门、景区运营方或合作机构。每份原件有来源、字段说明与摘要，产品修订引用原件，交付时按领取方、用途和来源辖区核对许可。受理人员应能区别来源事实、内部编排和已交付凭据。

当前项目围绕降级摘牌状态的来源裁决开展资料协作。正式公告、复核观察和运营材料各有发布主体；示例记录不代表真实景区状态。

## 等级裁决的三层关联

`exchange/ratings.py` 把三类事实分开登记、再关联到一个可追溯的当前等级视图：

1. **来源公告（`rating_documents`）**：每份公告对应一份原件资产（`assets`），记录发文日、生效日、接收日与接收序号、发布主体辖区和更正指向。公告类型包括授牌 `award`、整改 `rectification`、降级 `downgrade`、摘牌 `delist`、撤回 `withdraw`、主动退出 `voluntary_exit` 和更正 `correction`。
2. **决定效力（`rating_decisions`）**：公告导入后生成决定，状态为 `effective`、`open`（整改观察进行中）、`closed`（被后续决定更迭）或 `withdrawn`（被撤回/更正）。决定之间用 `supersedes_id` 记录更迭关系，按发文日和序列构成决定链。
3. **公开状态（`rating_publications`）**：同一份公告在门户 `portal` 与地方名单 `local_list` 的公开分别登记、各自留痕，公开时间不一致不影响决定效力。

业务人员通过 `current_view(spot_id)` 读取当前状态，状态取值为：

- `rectification` 待整改：整改观察进行中，展示等级继承整改前的有效等级；
- `downgraded` 已生效降级 / `delisted` 已摘牌 / `exited` 主动退出；
- `rated` 等级有效（含更正后恢复）；
- `unverified` 待核：存在未解决的证据冲突，或没有有效等级依据，此时 `level` 为 `null`，系统不推断等级。

视图中的 `basis` 直接指向所依据的公告与原件资产，`decision_chain(spot_id)` 可回溯链上每一次展示等级对应的文件。

## 不变量

- **重复导入幂等**：同一景区内，相同公告编号或相同原件摘要的导入直接返回既有编号，不产生新决定、不覆盖任何有效决定。
- **迟到不覆盖**：决定链按公告自身的发文日排序，而非导入时间；迟到导入且发文日更早、等级又与现行决定相反的文件不会覆盖有效决定，而是登记为 `late_import_contradiction` 冲突并保持待核。同发文日不同等级记为 `same_day_level_conflict`。正常更迭（发文日更晚的决定）不算冲突。
- **更正与撤回显式化**：更正/撤回必须指明目标文件；原决定置 `withdrawn`，更正文件携带等级时生成恢复等级的授牌类决定，不携带等级时维持整改观察。
- **辖区转移隔离**：转移生效日之后，旧辖区发布的公告标记为非管辖（`governing=0`），只留痕不产生决定；`spots.jurisdiction` 保留登记辖区，历史时点辖区由转移记录回溯。
- **冲突宁可待核**：冲突期间不展示推断等级，只给出全部候选依据；人工通过 `resolve_conflict` 明确胜出文件后才恢复展示，落选决定被标记撤回。
- **可交付**：`dossier_asset_ids(spot_id)` 汇总有效管辖公告的原件资产，可直接编入数据产品，沿用既有的许可、策略与交付回执链路。
